## Design assessment

R2 combines two responsibilities. Human questions are admission/routing work
owned by flows; Fold evaluates already admitted editorial records. Keeping a
second human-question lifecycle in desk states duplicates responsibility and
allows docket_of to bypass the admitted-input condition. Reuse the existing
queries_in_copies classifier at the single-copy flow boundary, then delete the
obsolete desk lifecycle and tests. Event ownership is a related boundary issue:
the stage report also includes envelope refusals and questions before Fold.
Its type vocabulary should belong to reporting, not claim every event is a
fold output. Existing event-log direction does not authorize implementing the
whole event log for this review.

R3 has two distinct causes. Text composition conflates equal operations with
competing operations, while effect dispatch conflates actions on a role's side
with actions on a move. Deduplicating whole side strings fixes equal complete
paragraphs but misses a shared edit when one side also changes another span.
Normalize equal edit operations in the composer, preserving named provenance
where refusal diagnostics need it. Apply each normalized operation once; simply
allowing equal meeting edits would duplicate inserted text when applying them.
Keep genuine conflicting replacements and distinct insertions without an
established order refused. Split the answer effect contracts by their subject
or provide equivalently typed exhaustive reducers; a generic enum plus silent
fall-through does not solve the ownership defect.

Current passes import machine.differences, contrary to #207. The existing
only-a-flow-reaches-the-machine task owns moving pure differences into a leaf.
Coordinate paths with that task rather than adding another boundary move or
letting the old path dictate the repair's architecture.
