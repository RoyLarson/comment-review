# The Turn Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the prototype turn (`bc62ea5`, `ce03d5e`) do what the rulings the five-hand
game produced say it does: agreement by text alone, a lone mark sent back, a determined place
final, the human's query carried, the cap closed only when every place is ruled. It stays a
PROTOTYPE by name until it has run once more as a game (Roy, 2026-09-04: *"Looks like a good
prototype"*): the banners on `desk/determined.py`, `desk/diff_mark.py` and `flows/turn.py`
stay, and what the banners say is kept true.

**Architecture:** No new module. `flows/turn.py` takes the sent batch and pairs answers to it;
`flows/collate.py`'s `_resolve` and `_identical` and `desk/collator.py`'s `reconcile` change
what agreement is; `Collated` and `MasterProof` gain the human's query; `Determined.deserialize`
tightens. Every step is a change to a function that exists, with the test that would have
caught the game's finding written first.

**Tech Stack:** Python 3.11 (floor, annotations EAGER), standard library only under
`src/comment_review/**`, `pytest`, `ruff`, `ty`.

**Plan steps this delivers:** `docs/plans/0.2.4-the-mark-and-the-collator.md` **P16, P17,
P19, P21** (P18 and P20 are ticked as prototype already). Those close
`TODO/a-revise-answer-has-no-artifact.md` **T13, T15, T17, T18, T27, T31, T32, T33, T34,
T35**.

**Rulings:** `decision-log.md Process: #86` (escalation answers with a DiffMark, composition
with a fresh Mark), `#87` (the chief's ruling is a Determined, one per resolved place, on the
master proof), `#88` (agreement is the text alone, every owing mark), `#89` (a lone owing mark
goes back to every role that marked but a query), `#90` (the human-review query rides and is
asked last; the other shapes abstain), `#91` (once stet, always stet, for the review).

## Two readings this plan takes as backend, stated rather than asked

- **A lone owing mark is a composition of one side** (Task 3). `#89` says it goes back to the
  roles that marked the place; the re-read slot then carries that mark's own text as
  `raw_text`, a `clean` from another role adopts it, and the next fold sees identical texts.
  That is the same mechanism a two-sided composition uses, and it lands a lone `add` (T13)
  without a special case.
- **A place every mark withdrew from is a `stet` of the original** (Task 6), `side = ORIGINAL`,
  `mark = None`, `how = "withdrawn"`. `#87` says every resolved place carries a Determined and
  `HOW` has no word for this today; `withdrawn` joins `one`, `identical` and `cap`.

## Global Constraints

- Run everything through `uv run`. Python **3.11** floor; annotations are EAGER.
- `desk/` is the MIDDLE and imports no `results/` or `docket/` module; `flows/` may import
  anything. `tests/test_areas.py` holds that line.
- No `except` clause in a shipped file holds a tuple literal.
- Test first, over real inputs: binders from `a_binder_over`, copies from the real `seed`,
  batches from the real `batch_of` over the real `collate`. A literal only where malformed is
  the input.
- After each task: `uv run ruff check .`, `uv run ruff format .`, `uv run ruff check .` again,
  `uv run ty check`, `uv run python scripts/check_shipped_syntax.py`, `uv run pytest -q`. One
  failure is expected on a branch: `tests/gates/test_build.py`.
- **Every task ends in two commits.** The work, with a message written to a file and passed
  with `-F`. Then the tick: the `T` on `TODO/a-revise-answer-has-no-artifact.md` closed against
  the work's sha, the `P` on the 0.2.4 plan where one closes, the plan refreshed, and this
  file's boxes below -- committed on their own, naming the work's sha.
- The game harness in the session scratchpad (`game.py`, `merge_marks.py`, `make_case.py`) is
  the end-to-end check and is not in the tree. Task 10 runs it.
