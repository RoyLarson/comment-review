## Evidence -- the blockers in detail

**Reference for the boxes above, not a second list of work.** Seven agents reviewed the address
system 2026-08-19 and returned 21 findings; these are the ones that stop a release, each
reproduced before it was written down.

### B1 -- one address names two blocks, on any mid-line comment

```
let b = 2; /* opens
and closes */
```
gives `@b1` to the comment (lines 2-3) **and** to an empty interval, and lines 2 and 3 each carry
two addresses. `record.entry_for("@b1")` returns the interval, so a record on the comment resolves
to the wrong entry and every text check reads `""`.

!! **The cause is two computations of one fact inside one module.** `addresser.address()` decides
"shares its line" from `kind in SHARES_ITS_LINE`; `code_lines_of` decides the same property from
`whole_lines`. A mid-line `comment` is `whole_lines=False` and not in `SHARES_ITS_LINE`, so it
takes a `b` folio for a line it sits on. **One computation, and `SHARES_ITS_LINE` goes.**

! This is a design fix, not a patch, and it is the claim `docs/addressing.md` and the CHANGELOG
currently overstate. Both must be corrected with it.

### B2 -- the `c` series cannot be written -- RESOLVED 2026-08-19

The join admits an `add` at `@c0` -- *"Every finding is admissible. Stage 5 may rule."* -- and the
galley refuses the splice, **discarding every other edit in that file with it**. Same for any
`patch`/`correct`/`drop` on an existing trailing comment, which is a real prose block owed a
record.

`margin` carries `whole_lines=False`, and `galley.shares_a_line_with_code` refuses exactly that.

!! **NEEDS A RULING.** Either the galley learns to splice within a line, or the `c` series is
addressable-but-not-writable and `reviewer-brief.md` says so. It cannot stay admitted-then-refused:
that is the pipeline saying yes at stage 5 and no at 5b, which `SKILL.md` calls the most expensive
diagnostic there is.

### B3 -- a fresh census reads as STALE on any lexical-tier trailing comment

```
census.py --json … tests/fixtures/sample.go     # seconds old
addresser.py --census go.json --check
STALE CENSUS  … 1 of 11 blocks no longer match  (exit 2)
```
`blocks_lexical` cuts `raw_lines[0]` at the comment opener, so `block_matches` compares
`// a trailing comment` against `\treturn a + b // a trailing comment`. Python is unaffected --
`blocks_stdlib` stores the whole line -- which is why no test catches it.

! It kills `--check`, `--resolve` **and** `--anchor/--series` before they dispatch, on every
non-Python file with a trailing comment or an indented block comment. The message is unactionable:
re-running reproduces it. **It also masks B1**, which is why B1 survived the measurement.

### B4 -- the 0.2.x reader is dead, and it is the only bridge to held runs -- SUPERSEDED 2026-08-19

A 0.2.x report carries `BLOCK 1 | a.py:1-2`; the reader puts that LINE address into
`Finding.address`, and the index translation is guarded by `if not f.address`, so it never fires.
`--convert` drops 100% of a held report and exits 0.

! Replaying held reports is how 0.2.1 and 0.2.2 were validated cheaply -- ~1.6M tokens of review
reused. **Fix: ignore the tail unless it holds an `@`, then fall through to the index.**

!! **SUPERSEDED 2026-08-19 -- THE DIAGNOSIS IS WRONG, THE FIX WOULD NOT HAVE WORKED, AND THE
GOAL IS NOT REACHABLE.** Measured: `parse_report` leaves `address` EMPTY on a 0.2.x record, so
there is no tail to ignore and the join's guard fires exactly as intended. Falling through to the
