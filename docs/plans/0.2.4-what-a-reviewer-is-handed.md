# 0.2.4 -- what a reviewer is handed

**Branch `feat/0.2.4-what-a-reviewer-is-handed`. The release is the ADDRESS: a place this system
names once, the same way, everywhere.** `docs/addressing.md` is the settled definition; this is
the scope of work that makes it true.

! **This is a `docs/plans/` plan, not a `docs/superpowers/plans/` one.** Roy, 2026-08-19: *"it is
not a superpowers plan and I don't want to conflate the rigorous one for the less rigorous one."*
A superpowers plan is written for an engineer with no context -- exact files, TDD steps, a commit
per task. This is a release scope: what ships, what does not, and what must be true first.

! **A PLAN is not a TODO.** Roy, 2026-08-19: *"Todos can remain open an indefinite amount of time
and make progress as we see fit. Plans are scopes of work to be complete in one run."* Anything
here that does not get done is filed in `TODO/` before this plan is closed, or it is lost --
`TODO/two-live-runs-proposed-fifteen-changes.md` held the 0.2.4 scope as a section header until
now, which is how a release scope came to live somewhere it could sit open forever.

## Blockers -- 0.2.4 does not ship until these are false

Seven agents reviewed the address system 2026-08-19 and returned 21 findings. These are the ones
that stop a release. Each was reproduced before it was written down.

### B1 -- one address names two blocks, on any mid-line comment

```
let b = 2; /* opens
and closes */
```
gives `@b1` to the comment (lines 2-3) **and** to an empty interval, and lines 2 and 3 each carry
two addresses. `record.entry_for("@b1")` returns the interval, so a record on the comment resolves
to the wrong entry and every text check reads `""`.

!! **The cause is two computations of one fact inside one module.** `addresser.address()` decides
"shares its line" from `kind in SHARES_ITS_LINE`; `code_lines_of` decides the same property from
`whole_lines`. A mid-line `comment` is `whole_lines=False` and not in `SHARES_ITS_LINE`, so it
takes a `b` folio for a line it sits on. **One computation, and `SHARES_ITS_LINE` goes.**

! This is a design fix, not a patch, and it is the claim `docs/addressing.md` and the CHANGELOG
currently overstate. Both must be corrected with it.

### B2 -- the `c` series cannot be written

The join admits an `add` at `@c0` -- *"Every finding is admissible. Stage 5 may rule."* -- and the
galley refuses the splice, **discarding every other edit in that file with it**. Same for any
`patch`/`correct`/`drop` on an existing trailing comment, which is a real prose block owed a
record.

`margin` carries `whole_lines=False`, and `galley.shares_a_line_with_code` refuses exactly that.

!! **NEEDS A RULING.** Either the galley learns to splice within a line, or the `c` series is
addressable-but-not-writable and `reviewer-brief.md` says so. It cannot stay admitted-then-refused:
that is the pipeline saying yes at stage 5 and no at 5b, which `SKILL.md` calls the most expensive
diagnostic there is.

### B3 -- a fresh census reads as STALE on any lexical-tier trailing comment

```
census.py --json … tests/fixtures/sample.go     # seconds old
addresser.py --census go.json --repo . --check
STALE CENSUS  … 1 of 11 blocks no longer match  (exit 2)
```
`blocks_lexical` cuts `raw_lines[0]` at the comment opener, so `block_matches` compares
`// a trailing comment` against `\treturn a + b // a trailing comment`. Python is unaffected --
`blocks_stdlib` stores the whole line -- which is why no test catches it.

! It kills `--check`, `--resolve` **and** `--anchor/--series` before they dispatch, on every
non-Python file with a trailing comment or an indented block comment. The message is unactionable:
re-running reproduces it. **It also masks B1**, which is why B1 survived the measurement.

### B4 -- the 0.2.x reader is dead, and it is the only bridge to held runs

A 0.2.x report carries `BLOCK 1 | a.py:1-2`; the reader puts that LINE address into
`Finding.address`, and the index translation is guarded by `if not f.address`, so it never fires.
`--convert` drops 100% of a held report and exits 0.

! Replaying held reports is how 0.2.1 and 0.2.2 were validated cheaply -- ~1.6M tokens of review
reused. **Fix: ignore the tail unless it holds an `@`, then fall through to the index.**

### B5 -- two files that dot alike share every address

`a/b.py` and `a.b.py` both dot to `a.b.py`, so `a.b.py@a0` names two blocks in two files.
`--check` reports "4 of 4 blocks addressed" with no SHARED, because `_check` compares only within
one path. `undot` refuses the ambiguity correctly, so the address is unresolvable later -- the
collision is admitted and surfaces as a failure somewhere else.

### B6 -- the brief teaches the numbering the ruling superseded

`reviewer-brief.md` and `addresser.py` both still carry *"The number means a different statement in
`b` than in `c`"*, written when `c` counted from 1. Since the 0-indexing ruling, `bN` and `cN` name
the same code line. **A reviewer following the brief cites `c(N+1)` for the line it means** -- the
off-by-one the paragraph warns about, inverted, in the file that costs 5x.

! The brief contradicts itself 118 lines later, where the newer text is right.

### B7 -- the shipped vocabulary is wrong in both directions

`vocabulary.toml` ships `block = "The interval between two lines of CODE"` to all six roles -- the
definition the 2026-08-19 ruling replaced -- and **`address` is not defined at all**, nor `margin`,
which is 30-50% of the rows a reviewer now reads.

! `check_vocabulary.py` reports "0 holes" because it checks that listed terms are defined. It
cannot notice a term of art the brief uses that nobody declared.
