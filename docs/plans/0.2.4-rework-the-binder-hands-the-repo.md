## What was measured, 2026-08-24

**The bytes are not where the field list said they were.** Re-measured against this tree, not
quoted:

| what | measured |
| --- | --- |
| the JSON census over one 500-line file | 115 rows, **71,100 bytes** |
| key names alone | **23,000 bytes, 32% of the file** -- 19 keys restated per row |
| `path` + `tier` | 10,005 bytes, 14% -- two strings, 115 times |
| six of nineteen keys | carry information on under 10% of rows |

!! **AND THE LISTING -- what stage 4 pastes to four roles -- IS 92% A LIST OF FILES IT IS NOT
REVIEWING.** `NOT CHECKED` is **279 lines, 31,434 bytes, byte-identical across every page**,
because it is a fact about the repo:

| file under review | census part | `NOT CHECKED` | share |
| --- | --- | --- | --- |
| `repo.py` | 41 lines | 279 lines | **92%** |
| `page.py` | 204 lines | 279 lines | **64%** |
| `constants.py` | 27 lines | 279 lines | **94%** |

**31,434 x 4 roles = 125,736 bytes a page**, saying the same thing each time, growing with the
REPO rather than with the work.

!! **THE FILTER IS NOT THE DEFECT, AND THAT WAS TESTED RATHER THAN ASSUMED.** Roy, 2026-08-24:
*"your statement about the filter presupposes that the filter is doing what it was supposed to do
and it currently isn't. Make a temporary edit to enforce that it actually drops all of the
records that have the absent cue marks and then rerun the test."* ! Done: `Kind.holds_no_prose`
answers True for all 105 of `repo.py`'s 115 non-prose rows, and making `--filtered` DROP them
outright instead of collapsing them into run lines saved **3.7%** over three files. **The run
lines are not where the bytes are** -- and a trim aimed at them would have been measured against
the wrong thing. `census.py` was restored and compared byte for byte.
