## Objective

**Every step of the chain is a command except the middle.** Measured 2026-08-29 by
running it end to end against two real files, with the shipped `block-context` agent
filling the sheet:

    census --json --out          a binder                        COMMAND
    mark --seed                  10 places for block-context     COMMAND
    the block-context agent      12 marks over those 10 places   AGENT
    mark --check                 12 ruled on, 0 left unruled     COMMAND
    gather / places / reconcile  settled 4, escalated 0          NO COMMAND
    docket_from                  2 pages, 4 alterations          NO COMMAND
    proof --docket               a revise, 0 refusals            COMMAND
    taken_in                     the diff                        COMMAND

`gather`, `places`, `reconcile` and `docket_from` are built and tested, and nothing
exposes them -- so that run drove them from a hand-written script. **The task agent
drives this pipeline by RUNNING COMMANDS, so it cannot reach reconciliation at all.**

! **THE REVIEWER HALF NEEDS NOTHING.** `mark --shape` and `mark --check` exist and a
reviewer neither seeds its own copy nor should be able to.

!! **AND THE COPY-CHIEF'S EDIT_COPY IS THE FINAL ONE.** Roy, 2026-08-29: the collation
produces one more `edit_copy` -- the copy chief's -- and the docket is a TRANSCRIPTION
of it rather than a computation over reconciliation's buckets. ! That is what makes
`docket_from` take ONE argument: it reaches into the `master_proof` today only to find
each page's `path` and `sha`, and an `edit_copy` already carries both on its sheets.

! **`Process: #42` STANDS: the copy-chief AGENT is 0.2.5.** Roy, 2026-08-29: *"the
copy-chief role is not in 0.2.4 it will be in 0.2.5. In 0.2.4 it will be handled by the
task agent. The commands for the copy-chief need to be in this release else there is
nothing to for the copy-chief todo."*

### Not in scope

! **`prove_unchanged` is not a middle command.** It is stage 7b's, run by
`references/write.md` against the PRE-EDIT REF after WRITE reaches the real tree.
Inside the revise chain `proof_setter` already proves each draft, so a second prove
there would be redundant. Roy, 2026-08-29: *"It is the responsibility of the
proof-setter pass."*
