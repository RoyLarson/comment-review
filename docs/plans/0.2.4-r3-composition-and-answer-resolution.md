## Objective

Apply equivalent edits once, retain every convergent move, and resolve each
answer with a complete subject-specific contract

## Design, scope and dependencies

Parent: [0.2.4-the-middle-rebuilt](0.2.4-the-middle-rebuilt.md), P25.
Branch: feat/r3-composition-and-answer-resolution, created from
feat/the-middle-rebuilt after its planning checkpoint a4c120af.
Specification and finding traceability:
[R3-A through R3-D](../reviews/2026-09-30-r2-r3.md).

Success is a review that can compose compatible proposals and finish a role's
deferral without losing the original filings or accepting prose a reader was
never shown. Equivalent text operations are deduplicated; the original marks,
roles and move identities are retained. Side changes and placement changes
have different closed effect contracts, with every admitted member handled.

Alternative assessed: deduplicating complete side strings alone would miss a
shared edit when another side also changes an independent span. Permitting
equal overlaps without normalizing their application would insert the same
text twice. Replacing several moves with one synthesized mark would lose
their origins and placement claims. Normalize operations in the pure composer
and retain the evaluator's original filings instead.

Python remains 3.11; shipped source uses the standard library alone. Use
`uv run` for every Python/test/gate command. Source lives in src/, and
plugins/ is generated only during release. This branch is not a release.
Read docs/conventions.md and docs/lanes.md before implementation; mechanical
import/path updates and shared vocabulary updates follow those agreements.

Preserve Processes 179, 180, 195 and 196. Processes 123/124 govern acceptance
and escalation after a composition rewrite: composing text does not imply
all readers accepted it. Preserve human-question admission under 197/198.
Do not decide the separate initial-mark versus answer-payload ruling here.
Do not add middle-side page reads or drift checks. R2's obsolete human-state
removal, the event-log redesign, chief-copy repair and remaining machine I/O
relocations are separate goals.

P1 precedes P2/P3 so composition changes belong to the leaf selected by 207.
P2 supplies the operation semantics exercised by P3. P4 repairs deferral
behavior independently, then P5 makes dispatch exhaustive while preserving
P4's observed result. P6 follows all delivered units. These dependencies are
explicit; P numbers themselves do not determine execution order.
