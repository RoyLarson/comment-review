### What each of the six covers

`docs/the-turn.md` is the SOURCE for the loop; this is the map from that file
to these tasks. **It is not a sequence** -- a `P` is a task that makes a `T`
accomplishable, and the ordered list is an `SP`'s (`docs/conventions.md`).

| the part of the loop | task |
| --- | --- |
| a role's answer to a disagreement is its own artifact | `P20` |
| every disagreement goes out at once, one payload per role | `P21` |
| the answers come back and parse | `P16` |
| what resolved joins the chief's `edit_copy` -- **that is a round** | `P17` |
| the run says how many rounds it took, and of what kind | `P18` |
| at the cap, the chief rules on what is left | `P19` |

!! **`P3` NO LONGER SAYS THE RIGHT THING AND IS SUPERSEDED BY `P18`.** It reads
*"Update the round CAP to say what it counts"*, which presumes a cap the code
holds -- and `Process: #78` rules the cap is what the task agent is told, never
what the code enforces. **What survives is the counting**, which is `P18`.
