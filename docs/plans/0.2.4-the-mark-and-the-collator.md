# 0.2.4 -- the mark, the revise, and the collator

**The middle.** A role hands back marks; something checks each one against the page it rules on,
reconciles what several roles said about one place, emits a conflict for the ones that disagree,
and **pulls a revise so the next stage reads what the last one settled.** That is `collator.py`
and the revise pull, and neither exists.

**Branch:** `feat/the-mark-and-the-collator`, off `feat/0.2.4-what-a-reviewer-is-handed`.

## The shape this plan is written against

!! **THE ROLES DO NOT ALL READ THE SAME PAGE AT THE SAME TIME, AND NEVER DID.** Roy, 2026-08-28,
on the first draft of this plan: *"it bakes in the idea that all editorial-role agents see
everything at the same time and only rule on it once."* `SKILL.md` stage 4 already runs
`ownership-context` alone at 4a and the other three at 4c, and at least one further agent is
expected before those three.

```
                 ORIGINAL  (--repo .)
                      |
   enriching stage    |   facts -> into the next binder. No docket, no revise
                      v
   stage 1  ownership-context          sheet -> marks
                      |                 verify -> reconcile -> revise step -> docket
                      v                 proof_setter --out revise-1  +  prove_unchanged
                 REVISE 1  (a tree copy, the drafts overlaid)
                      |                 ASSERT the address set equals the original's
                      v
   stage 2  block / function / module, one message, blind to each other
                      |                 same four steps
                      v
                 REVISE 2   ==   the draft the human approves at 7a
```

Every editorial boundary is the same four steps -- **verify, reconcile, revise, pull** -- and the
last one's output is what 7a reads. There is no separate backward phase and no stage is ever
re-entered.

| | holds because |
| --- | --- |
| **the address space never moves** | `prove_unchanged` holds the code byte-identical, and a place is determined by CODE. Gated by re-censusing each revise |
| **the forward pass is a line** | a reversal is a ROW on the revise sheet at that boundary, between the two roles that disagree -- not a re-run |
| **one root per stage** | a `source` citing a page an earlier stage edited must read that page's current text |
| **one mechanism, four uses** | the pull feeds the next stage, feeds the revise step, feeds 7a, and runs `prove_unchanged` every time |
| **the run terminates** | two rounds per place, then the copy chief -- `Process: #9`, ruled 2026-08-24 |

! **THE MECHANISM IS MOSTLY BUILT.** `flows/proof_setter.py` already sets a page and writes a
draft into `--out DIR` -- *"a temporary file, never the original"* -- proving executable code
unchanged and refusing a draft directory that overlaps the repo. And `census`, `carry`, `proof`,
`prove_unchanged` and `referrers` all already take `--repo`, so pointing a stage at a revise is
passing a different value.

## The constraint every step is written under

!! **NO TEST IN THIS BRANCH TAKES ITS EXPECTATION FROM THE CODE UNDER TEST.** Roy, 2026-08-28:
*"Tests that test themselves are not useful tests."* `decision-log.md Vocabulary: #23`.

| | |

| an **expectation** may come from | the shipped prose that states the contract, a recorded run's output, or a literal a human checked |

## P3 -- source-verification

Per MARK, against the page it rules on, in the root that stage was given. `Vocabulary: #19`.

and the look up time each time."* ! Nothing ruled says a mark must be refused because its page
