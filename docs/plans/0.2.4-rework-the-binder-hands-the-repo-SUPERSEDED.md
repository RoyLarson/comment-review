## What was measured, 2026-08-24

!! **THE JSON CENSUS IS WHERE THE COST IS, AND `--filtered` DOES NOT TOUCH IT.** Measured: `--json`
returns **115 rows and 73,792 bytes with or without `--filtered`, byte-identical.** Everything the
listing does to collapse no-prose rows is absent here.

| file under review | rows | hold prose | JSON | x4 roles |
| --- | --- | --- | --- | --- |
| `constants.py` | 34 | 4 | 25,630 | 102,520 |
| `repo.py` | 115 | 10 | 71,099 | 284,396 |
| **`page.py`** | **659** | **60** | **429,239** | **1,716,956** |

**One page of `page.py` is 1.7 MB across four roles.** And what each trim takes off it:

| | `repo.py` | `page.py` |
| --- | --- | --- |
| minus the 12 fields that carry nothing | **46%** | **45%** |
| prose rows only | 24% | 27% |
| **both** | **2%** -- 2,109 b | **2%** -- 12,651 b |

! Inside the JSON: **key names alone are 23,000 bytes, 32% of the file** -- 19 keys restated on
every row -- and `path` + `tier` another 14%, two strings repeated 115 times.

### The listing is a different artifact with a different defect

`NOT CHECKED` is **279 lines, 31,434 bytes, byte-identical across every page**, because it names
every tracked file the harvester cannot read, at ABSOLUTE paths. It is 92% of `repo.py`'s
listing, 94% of `constants.py`'s, 64% of `page.py`'s. ! **It does not appear in the JSON at all**,
so it costs a reviewer handed JSON nothing -- which is why it sits at the END of this plan rather
than the front.

!! **AND THE FILTER IS NOT THE DEFECT, WHICH WAS TESTED RATHER THAN ASSUMED.** Roy, 2026-08-24:
*"your statement about the filter presupposes that the filter is doing what it was supposed to do
and it currently isn't."* ! Tested: `Kind.holds_no_prose` answers True for all 105 of `repo.py`'s
non-prose rows, and making `--filtered` DROP them outright rather than collapse them into run
lines saved **3.7%**. The run lines are not where the bytes are. `census.py` was restored and
compared byte for byte.

### The split was already built once, by hand, and never reached the tool

A full v0.2 dogfooding run -- evidence held outside this repo, with the corpus it ran over --
produced **two census artifacts**: the full one for the machine, and a prose-only one for the
reviewer holding **171 of 3,333 blocks, 5.1%**. The dispatch packet was split the same way, one
copy as filled and one as pasted.

! **So this plan is not proposing a new shape.** It is landing one that a real run needed badly
enough to build by hand.

!! **BUT THE 2026-08-18 RULING BEHIND IT MAY NO LONGER BE NECESSARY, AND SAYING SO IS P7.** That
ruling -- on
[`the-census-is-mostly-intervals-nobody-rules-on`](../../TODO/the-census-is-mostly-intervals-nobody-rules-on.md),
*the census stays fully enumerated ON DISK, the agents get a FILTERED view, and a destination
outside their set comes from a TOOL answering one question* -- was made under a condition that
has changed. Roy, 2026-08-24: *"this was ruled when I couldn't trust the system to work period.
It may not be necessary now, because page loading and address querying should be able to return
the record correctly without messing up the rest of the system."*

! **A PRE-FILTERED FILE IS WHAT YOU BUILD WHEN YOU CANNOT ASK.** The filtered view exists so a
reviewer holds a smaller copy; a binder that answers *give me this page* or *what is the address
of this line* makes the copy unnecessary rather than smaller. **The two answers are not a
preference between formats -- one of them deletes an artifact.** ! That is `decision-log.md
Addressing: #9`, the binder as a thing you ASK rather than a file you are handed.

! **So the split is carried here as a QUESTION, not as a settled design**, and the hand-built
precedent above is evidence that the need was real in 2026-08 -- not evidence that it is real
now.
