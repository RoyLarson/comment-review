# 0.2.5 -- the foliator owns the address

**Branch `fix/folio-placement-is-not-where-the-anchor-is`. The release is the FOLIATOR: one walk
that emits every address and the anchor it is attached to, owned by one module, so nothing else
computes a place.** 0.2.4 settled what an address IS. This settles who MAKES one.

! **This is a `docs/plans/` plan, not a `docs/superpowers/plans/` one.** A superpowers plan is
written for an engineer with no context -- exact files, TDD steps, a commit per task. This is a
release scope: what ships, what does not, and what must be true first.

! **A PLAN is not a TODO.** Todos remain open indefinitely and progress as we see fit; a plan is a
scope of work to be completed in one run. Anything here that does not get done is filed in
`TODO/` before this plan closes, or it is lost.

- [x] **A2 -- the census stops setting anchors.** DONE `b342cd1`. The anchor now comes from

      Works [`census-owns-addressing`](../../TODO/census-owns-addressing.md).

- [ ] **A3 -- each of the four modules announces ONE subject**: `foliation` names places, `page`
      says what a page and a paragraph are, `census` says which prose occupies which address,
      `galley` sets the proposed text. Verify by running `module-context` over all four. Works
      [`census-owns-addressing`](../../TODO/census-owns-addressing.md).

- [ ] **A4 -- the galley applies edits BY SERIES, never by line.** `b0`, then `a0`, then
      a -> b -> c. `splice` sorts on `(start, end, column, replacement)` and applies descending by
      line, which is what makes an `a`/`b` tie fall to the reviewer's quote style. Works
      [`b-foliator-uninitialised`](../../TODO/b-foliator-uninitialised.md) and closes
      [`galley-is-still-index-keyed`](../../TODO/galley-is-still-index-keyed.md).

      !! **THE ORDER IS UNIVERSAL, AND IT IS AN APPLICATION ORDER -- NOT A LINE ORDER.** Roy,
      2026-08-20: *"`a` has to be put in first because it is the 'inner most' documentation -- the
      `b` gets applied in the rows outside-beyond it."* Two edits inserting at ONE point are not
      a conflict: the second lands ABOVE the first, so applying `a` first puts `b` outside it. A
      Python docstring sits INSIDE the body and a Rust `///` sits ABOVE the `fn`, and the same
      order is right for both -- no language needs to state which side its doc goes on. `b0`
      before `a0` is the same rule, applied to the module.

      !! **MEASURED 2026-08-20, and neither half is expressible today.** `splice` re-sorts its
      own argument, so `[a, b]` and `[b, a]` produce BYTE-IDENTICAL output -- the caller cannot
      say the order at all. The tie therefore falls to the ASCII of the replacement text: `//` <
      `///` puts Rust's gap prose outside the doc comment, which satisfies the ruling **by
      accident**, while `"""` < `#` applies Python's comment first and leaves the docstring ABOVE
      it, which does not.
