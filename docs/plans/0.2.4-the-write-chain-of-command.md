## The two endpoints

Roy, 2026-08-25: *"The workflow stops at making a temporary file for the human to review. The
final human-review human-edit machine-review machine copy is its own workflow."*

**It opens** on the notations the agent workflow emits, beside the saved binder.
**It closes** on a temporary file per page, proven to hold only comment changes.

```
  notations {address: text | None}        the SAVED binder
              \                          /
               +---> resolve the address                 -> path + cue
                            |
                            v
                  reload the page FROM DISK               page_for
                            |
                  sha == the sha RECORDED in the binder?  else REFUSE this file
                            |
                            v
                  galley.reset(page, {cue: text | None})
                            |
                            v
                  compositor.set_page(page)
                            |
                            v
                  draft -> a temporary file
                            |
                  read that file back AS A PAGE           did each cue take its text
                            |
                  prove_unchanged                         only comments changed
                            |
                            v
                       the human                          <- THIS WORKFLOW ENDS HERE
```

## P2 -- the file is the one that was reviewed

!! **THE ORIGINAL SHA IS A VALUE READ OUT OF THE SAVED BINDER, AND IS NEVER RECOMPUTED.** Roy,
2026-08-25: *"we can't assume that the file didn't change between original read and loading to
write and so getting it out of the json blob is important."* ! A sha derived from a file at
write time answers *is this file equal to itself*, which cannot fail -- the same shape as the
round trip that scored 699 of 699 while setting from the positions it had just read. **The
recorded value is the only one that can disagree.**

!! **AND IT ANSWERS A SECOND QUESTION, WHICH IS NOT A FILE-SYSTEM ONE.** Roy, 2026-08-25:
*"This also ensures that agents didn't try to fix what they found while reviewing."* The four
roles are read-only and MARK is separated from APPLY precisely so that fixing what you find
cannot destroy the finding. **Nothing in the tree proves they obeyed.** This check does, as a
by-product: a reviewer that edited the file under review moves the sha, and the run refuses.

!! **THE QUERY SHOULD NEVER HAVE LEFT `machine/`, AND THE DIRECTION IS THE WHOLE OF IT.** Roy,
2026-08-25: *"Because this is io/git/third-party software the querying of it should not have
left the machine/ modules. It is information received by page and binder, not something
requested by page/binder."*

! **TODAY THE BINDER ASKS.** `bind()` calls `sha_of(page.text)` -- the binder reaching out to
hash a file it was handed. Under the ruling the READ supplies the sha with the text, the page
RECEIVES it, and the binder reports what the page already carries. ! That is also what
`a-page-carries-no-identity` T1 says in as many words -- *"record the source SHA on the page,
beside `path`"* -- which the compute-it-in-`bind` form satisfied only in effect.

!! **AND THE READ IS THE ONLY PLACE THE COMPARISON CAN MEAN ANYTHING.** Roy, 2026-08-25: *"that
is the only place to properly ensure it gets read exactly the same and the middle things
shouldn't depend on the external things."* **MEASURED 2026-08-25** over
`b"# one\r\ndef f():\r\n    return 1\r\n"`, with this tree's two readers:

| reader | sha | text |
| --- | --- | --- |
| `repo.read_raw` -- `newline=""` | `f13497990c3d92d0` | `'# one\r\ndef f():\r\n    return 1\r\n'` |
| `Path.read_text` -- universal newlines | `83ec58343641fd11` | `'# one\ndef f():\n    return 1\n'` |

**One file, one set of bytes, two shas.** A sha taken downstream of whichever reader a consumer
happened to use answers *did the file change* with *which reader ran* -- so a byte-identical
file refuses, and the check that exists to catch a shifted file fires on a CRLF checkout
instead. ! Taking it AT THE READ removes the variable rather than documenting it.

! **THIS IS WHAT MAKES P5's `read_raw` BOX LOAD-BEARING** rather than tidiness:
`compositor.py:302` and `:333` are two of the `read_text` sites above.

- [ ] Move `sha_of` into `machine/`, beside the reading it belongs to. Verify: `hashlib` is
      imported in `machine/` and nowhere else in the package.
- [ ] The page RECEIVES its sha from the read. Verify: `Page` carries it beside `path`, and
      neither `page.py` nor `binder.py` computes one. Works `a-page-carries-no-identity` T1.
- [ ] The binder REPORTS `page.sha` rather than deriving it. Verify: `bind` calls no hash.
- [ ] Read the recorded sha out of the saved binder, per page. Verify: the value compared
      against is the one the binder emitted, and no path recomputes it from a file.
- [ ] The chain refuses a file whose bytes are not the ones the binder recorded, BEFORE any
      edit. Verify: a one-byte edit to a file under review refuses that file, and no draft is
      written for it. Works `a-page-carries-no-identity` T2 and T3 AS RESTATED below.
- [ ] The per-paragraph comparison's comment names the SHA as what answers *did the file shift*.
      Works `a-page-carries-no-identity` T4.

!! **T2 AND T3 OF THAT FILE ARE RESTATED BY THE 2026-08-25 RULING, NOT DELETED.** They read
*"make the GALLEY refuse"* and *"make the COMPOSITOR verify"*; Roy put the check in the chain
instead, so one owner answers it once rather than two owners answering it twice. The work is the
same work and the file is `backend`'s, which is why this plan restates rather than files a new
one.
